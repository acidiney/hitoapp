# Implementation status

The full release scope is in [release-plan.md](release-plan.md). This repository is a development build. The public release is not ready.

## Current quality work

The structural refactor, first substantial UI composition pass, tag-independent recording identity, multiple-folder Settings, artist/album pages, personal recording and album title/artist fields with source provenance, and personal HTTP plugin installation are implemented. Rust uses cohesive capability services with private SQLite storage, opaque authenticated actors, explicit backend device ownership, small HTTP adapters, and generated contracts. React uses focused pages and workflow hooks, a recording spotlight and artwork grid/list, grouped navigation, a listening sidebar, expanded player, and tabbed settings. Development setup launchers generate read-only Docker mounts from native folder selections. See [architecture decisions](architecture-decisions.md), [interface direction](../DESIGN.md), [folder behavior](music-folders.md), and the actual [TODO checklist](../TODO.md).

Provider search and adoption now have authenticated application APIs, live connection authority, and durable owner-only recordings with provider provenance. The existing audio API can relay provider bytes through a separate bounded media client. The discovery UI searches, pages, saves, and plays through those APIs. Artist pages include selected recording credits, including provider tracks without albums or sources, alongside real album appearances. The normal server is healthy on migration 0023 after a stopped-volume backup and read-only preservation audit. Core now issues session-bound playback grants for the planned native coordinator; actual output supervision remains unfinished. Source-only provider refresh, bounded browser failover near the requested seek position, and explicit track-details availability checks are implemented. Debrid preparation, native recovery, and full recovery acceptance remain unfinished. See [the content protocol and boundaries](plugins.md#provider-content-groundwork).

## Playback access verification

Core now issues an opaque `PlaybackSource` for an authenticated recording/source pair. It pins session identity/expiry, a durable membership grant, and the local folder or shared provider authority.
