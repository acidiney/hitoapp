# Implementation status

Updated 2026-10-16. The full release scope is in [release-plan.md](release-plan.md), with remaining work in [TODO.md](../TODO.md). Hito is a development build. The public release is not ready.

## Current behavior

Core owns identity, catalog, collection transactions, indexing and private SQLite storage. HTTP adapters authenticate through the shared extractor and map typed capability requests and results. Actual Rust routes generate OpenAPI and TypeScript. React pages use workflow hooks for async work; playback position updates do not rerender catalog pages. See [architecture decisions](architecture-decisions.md) and [interface direction](../DESIGN.md).

The library supports multiple server music folders, independent scans and removal/reconnection. Recording identity is separate from tagged-file checksums. Artist and album pages use exact library-scoped credits, release appearances, tagged order and scoped artwork. Personal recording and album title/artist edits retain source provenance and remain private. Development setup launchers generate read-only Docker mounts from native folder selections. Automatic desktop discovery and live platform setup acceptance remain open. See [folder behavior](music-folders.md) and [catalog browsing](catalog-browsing.md).

Personal HTTP plugin connections support administrator-offered addresses, manifest review, encrypted optional credentials, search, durable owner-only adoption and bounded authenticated audio relay. Discover can search, page, save and play provider recordings, including recordings without releases. Source-only refresh and bounded browser/native recovery recheck live authority. Debrid preparation, source preferences and complete recovery acceptance remain unfinished. See [plugin contracts](plugins.md).

The shared player uses browser audio on the web and a Rust command owner in desktop. Rust owns native queues, fenced commands, authorized output, source recovery, seek/volume and ordered progress. Previous follows played occurrences; shuffle/repeat retain stable entries. Nonunit 0.5–3× speed preserves pitch for supported 8–192 kHz mono/stereo sources. Ordinary 1× retains decoder support through 384 kHz subject to device support. Above 192 kHz, nonunit processing fails visibly and the same paused occurrence can retry at 1×. Explicit History resume loads current authorized progress with pending-write and stale-result fencing. Temporary authority failures suspend output and retain the process-local queue; definitive session rejection clears ownership. Durable queues, offline operations, physical output and packaged desktop acceptance remain open. See [native ownership and data flow](native-coordinator.md).

## Isolated plugin integration checkpoint

The isolated integration source adds [playlist Import a copy](playlist-import.md) through the SDK, core, HTTP, generated contracts and React, plus the folder plugin's private durable registry and witnessed release reconciliation. Copies preserve order, duplicate and retained entries, attribution and account privacy. Exact retries recover the original atomic receipt. Strict client synchronization input remains separate from immutable server publications.

Integration source `d483ad5` contains the final folder fixes. They check the original state-path ancestry and alias targets through trusted directory handles, preserve native state names on Linux, and verify the selected source's bytes before emission. Full aligned 64 KiB chunks are checked against snapshot SHA-256 proofs in a private bounded buffer, including during byte-range responses. The proof belongs to the selected representation, independently of the metadata owner. These fixes do not change the wire contract or SQLite schema.
