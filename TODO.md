# Hito TODO

Updated 2026-11-02. This is the remaining implementation work, not a list of features claimed complete. The full requirements and release gates are in [the release plan](docs/release-plan.md).

Multiple music folders are implemented in administrator Settings, with independent scans and removal/reconnection. Development setup launchers use native folder choosers and generate read-only Docker mounts without requiring `HITO_MUSIC_FOLDER`. Their live platform acceptance is still pending. Recording identity is separate from tagged-file checksums. Track and album details now support private title and artist edits with local source provenance. The server and web build run in Docker on the local development server (migrations through 0081 as of 2026-11-02). That is not a public release, and the open items below still block one.

Automatic audio resolution for imported playlists is deployed locally. Controlled browser workflows and one real Spotify-to-YouTube WebKit target pass without per-track URLs or manual matching. Existing YouTube connections must explicitly approve the added metadata capability. Manual source selection corrects a result; broader synchronization, matching, native and release acceptance remain open. See [current implementation, evidence and gaps](docs/automatic-sources.md). Visual polish remains after release functionality.
