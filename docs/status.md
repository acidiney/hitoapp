# Implementation status

The full release scope is in [release-plan.md](release-plan.md). This repository is a development build. The public release is not ready.

## Current quality work

The structural refactor, first substantial UI composition pass, tag-independent recording identity, multiple-folder Settings, artist/album pages, personal recording and album title/artist fields with source provenance, and personal HTTP plugin installation are implemented. Rust uses cohesive capability services with private SQLite storage, opaque authenticated actors, explicit backend device ownership, small HTTP adapters, and generated contracts. React uses focused pages and workflow hooks, a recording spotlight and artwork grid/list, grouped navigation, a listening sidebar, expanded player, and tabbed settings. Development setup launchers generate read-only Docker mounts from native folder selections. See [architecture decisions](architecture-decisions.md), [interface direction](../DESIGN.md), [folder behavior](music-folders.md), and the actual [TODO checklist](../TODO.md).

Provider search and adoption now have authenticated application APIs, live connection authority, and durable owner-only recordings with provider provenance. The existing audio API can relay provider bytes through a separate bounded media client. The discovery UI searches, pages, saves, and plays through those APIs. Artist pages include selected recording credits, including provider tracks without albums or sources, alongside real album appearances. The normal server is healthy on migration 0023 after a stopped-volume backup and read-only preservation audit. Core issues session-bound playback grants, and a Rust command/queue owner drives native output, bounded recovery, seek/volume, and ordered progress persistence through core services. Authenticated native HTTP and retained desktop cleanup are implemented. The shared player uses the native Rust owner in desktop and preserves browser playback on the web. Temporary authority failures suspend output and retain the process-local queue until access is rechecked; definitive session rejection clears ownership. Source-only provider refresh, bounded browser failover near the requested seek position, and explicit track-details availability checks are implemented. Debrid preparation and full recovery acceptance remain unfinished. See [the content protocol and boundaries](plugins.md#provider-content-groundwork).

The first [music-folder plugin demo](plugin-folder.md#running-legacy-demo) is running for local testing at `http://plugin-folder:8090/` from Hito, with a manifest at `http://localhost:8091/v1/manifest`. Its three generated WAV signals pass real UI installation, search, adoption, playback, seeking and removal. Each listener connects it personally; the agent has not installed a connection in the normal account. New registry and playlist-copy source has the separate evidence below. Spotify import, YouTube streaming and the other reference providers remain unfinished.
